Layered architecture. Network software is organised as a stack of layers so that each layer solves one problem and hides the details from the layers above it. A layer offers services to the layer above through an interface and talks to its peer on another machine using a protocol. Layering makes it possible to replace the implementation of one layer, for example swapping copper for fibre, without changing the rest of the stack. The cost of layering is some duplicated work and extra headers on every message.

OSI reference model. The OSI reference model divides communication into seven layers: physical, data link, network, transport, session, presentation and application. The physical layer moves raw bits over a medium. The data link layer turns that raw bit stream into frames that are free of undetected errors. The network layer routes packets from source to destination across several hops. The transport layer provides end to end delivery between processes. The OSI model is mainly used today as a vocabulary for describing where a function belongs, because its own protocols were never widely deployed.

TCP/IP model. The TCP/IP model has four layers: link, internet, transport and application. It was defined after its protocols already worked, so the model describes real software rather than an ideal design. The internet layer uses IP to deliver packets without guarantees, which is called best effort delivery. The transport layer offers TCP for reliable byte streams and UDP for simple datagrams. Compared with the OSI model, the TCP/IP model merges the session and presentation functions into the application layer.

Transmission media. Guided transmission media carry signals along a physical path. Twisted pair is cheap and common in local networks but is limited by attenuation and crosstalk. Coaxial cable has better shielding and higher bandwidth. Optical fibre carries light pulses through glass, which gives very high bandwidth, low attenuation and immunity to electromagnetic interference, at the price of more expensive interfaces. Unguided media such as radio and microwave links need no cable but share the spectrum and are affected by obstacles and weather.

Framing. The data link layer breaks the bit stream into frames so that errors can be detected and a damaged frame can be sent again. Framing needs a way to mark where a frame starts and ends. Byte stuffing uses a special flag byte and inserts an escape byte whenever the flag appears inside the data. Bit stuffing uses the flag pattern 01111110 and inserts a zero after five consecutive ones in the data, so the flag can never appear by accident. The receiver removes the stuffed bytes or bits before passing the data up.

Error detection with CRC. A cyclic redundancy check treats the bits of a frame as the coefficients of a polynomial. The sender divides the message, extended with zero bits, by an agreed generator polynomial using modulo two arithmetic and appends the remainder as the checksum. The receiver divides the received frame by the same generator, and a remainder other than zero means the frame was damaged. A CRC with a generator of degree r detects every burst error of length r or less, which is why CRC is preferred to a simple parity bit on noisy links.

Sliding window protocols. A sliding window protocol lets a sender transmit several frames before it needs an acknowledgement. Each frame carries a sequence number, and the window is the set of sequence numbers the sender may currently use. In go back N the receiver accepts frames only in order, so one lost frame forces the sender to resend every frame after it. In selective repeat the receiver buffers frames that arrive out of order and the sender resends only the lost frame, which wastes less bandwidth but needs more memory at the receiver.

Medium access control. When many stations share one channel, a medium access control protocol decides who may send. In pure ALOHA a station transmits whenever it has data and collisions are repaired by retransmitting after a random delay. Carrier sense multiple access improves on this by listening before sending. CSMA with collision detection, used by classic Ethernet, also listens while sending and stops as soon as a collision is detected, then waits for a random time chosen by binary exponential backoff before trying again.

IPv4 addressing. An IPv4 address is 32 bits long and is written as four decimal numbers separated by dots. The address is split into a network part and a host part, and the prefix length says how many leading bits belong to the network. Classless inter domain routing allows prefixes of any length, so address blocks can match the size of an organisation. Subnetting divides one block into smaller networks, and routers forward a packet using the longest prefix that matches its destination address.

Routing algorithms. A routing algorithm decides which outgoing line a packet should take. In distance vector routing each router keeps a table of the best known distance to every destination and periodically shares it with its neighbours, which is simple but suffers from the count to infinity problem after a link fails. In link state routing each router learns the full topology by flooding link state packets and then runs Dijkstra's shortest path algorithm, which converges faster at the cost of more memory and computation.

Congestion control. Congestion happens when more packets enter part of the network than it can carry, so queues grow, delay rises and packets are dropped. TCP controls congestion with a congestion window that limits how much unacknowledged data a sender may have outstanding. In slow start the window doubles every round trip until it reaches a threshold, after which congestion avoidance increases it by one segment per round trip. When a loss is detected the sender cuts the window, which is known as additive increase and multiplicative decrease.

TCP connection management. TCP sets up a connection with a three way handshake. The client sends a segment with the SYN flag and an initial sequence number, the server replies with a segment carrying both SYN and ACK, and the client acknowledges the server's sequence number. Using three messages protects against delayed duplicate connection requests. A connection is released separately in each direction with FIN segments, so one side can finish sending while it still receives data from the other side.
